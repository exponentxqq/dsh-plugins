# 折扣复测手册（verify-discount）

> 回答一个问题：**现在 zcode-plan 路由是否吃着官方 ZCode 折扣计费（1.5 倍用量）？**
> 判定键 = 请求签名通道（Ed25519 + PoW 头组），不是 Key 类型、不是端点、不是表层 header——
> 这些维度已在 2026-11 的定位实验里逐一排除（见 `acceptance.md` §二）。

## 一、原理与判据

官方「ZCode 1.5 倍用量」的字面实现 = **同等调用量按 0.67 系数折算计量**（1/0.67 ≈ 1.49x）。
复测方法是把这把尺子直接量出来：

- **两臂同凭据**：同一张 PAT，臂 A 带插件线全套签名头组（`replicate-sign-pat.mjs` 逐字
  复刻 `src/host/bigmodel/{signing,signer}.ts` 的协议常量），臂 B 无签名直连 curl——
  **唯一变量 = 签名**；
- **读数**：两臂各发一份互异全新 52000 字符体，用登录 JWT 读
  `GET https://www.bigmodel.cn/api/monitor/usage/quota/limit`，取 `unit===3`（5h 窗）与
  `unit===6`（周额度）两池请求前后的 `currentValue` 差值（credits）；
- **归一**：理论积分 = (非缓存输入 × 2.3 + 缓存命中 × 1.7 + 输出 × 24) / 10000
  （GLM-5.3 官方系数；**勿用 分/ktoken**——输出系数是输入的 10 倍，输出长度会污染归一），
  刻度 = 实扣 ÷ 理论积分；
- **判定**：比值 A/B（签名刻度 ÷ 无签名刻度）落 **0.50–0.75**（0.67 邻域）→ 折扣生效；
  两臂同价（比值 ≈ 1.0）→ 签名未生效。

比值判定天然**免疫绝对刻度漂移**：时段计量系数、tokenizer 压缩率变化、套餐基数调整
都同时作用于两臂，只在比值里相互抵消（2026-11-04 实测：同日 11:05 与 16:05 两轮绝对
刻度差 ~2 倍，比值稳定 0.617 / 0.679）。

## 二、脚本清单（`plugins/zcode-plan/scripts/`）

| 文件 | 职责 | 消耗额度 |
| --- | --- | --- |
| `refresh-snap.mjs` | 从 dsh 凭据存储提取登录 JWT / org / project / 现行 PAT，0600 写入 `WORK_DIR` 点文件；stdout 只出非机密诊断（效期、keyId 前 8 位、指纹） | 否 |
| `replicate-sign-pat.mjs` | 签名臂探针：PAT 三段式握手 + Ed25519 签名 + PoW，发一个请求体并报 `theory`；`HANDSHAKE_ONLY=1` 只验握手（预检） | 默认是；`HANDSHAKE_ONLY=1` 否 |
| `gen.mjs` | 生成互异等长全新请求体（时间种子，臂间无共享前缀——防前缀缓存假阳性） | 否 |
| `read-pools.mjs` | quota/limit 响应归一器：stdin 进 JSON，stdout 出 `u3=… u6=…` | 否 |
| `verify-discount.sh` | 总编排：本底窗 + 交错双对 + 平台期轮询 + 判定（下节流程） | **是**（4 探针，峰时实测 ~84 分） |

快照与请求体一律写 `WORK_DIR`（默认 `${XDG_CACHE_HOME:-~/.cache}/zcode-rate-test`，
可用环境变量覆盖）——**机密永不进仓库**。`package.json` 便捷入口：
`pnpm discount:snap`（= refresh-snap.mjs）、`pnpm discount:verify`（= verify-discount.sh）；
刻意**不**接入 `verify:all`（真金白银 + 依赖登录态）。

## 三、测试流程

```bash
cd plugins/zcode-plan

# 0) 前置自检：登录 / Key / PAT / 路由 / 签名 / 用量六行全绿，签名行不得是止损/冷却
#    （在 dsh 会话里执行，非本目录脚本）
/zcode-plan status

# 1) 刷新快照（PAT 满效期 5h，旧快照必过期；诊断行核对 PAT.exp 还有余量）
pnpm discount:snap

# 2) 零消耗预检：只验握手链路（get_sign_key + 私钥解密），不发模型请求
PAT=$(cat "$XDG_CACHE_HOME/zcode-rate-test/.pat" 2>/dev/null || cat ~/.cache/zcode-rate-test/.pat) \
  HANDSHAKE_ONLY=1 node scripts/replicate-sign-pat.mjs
#    期望输出：handshake_only=ok（失败先看 /zcode-plan status 与 signing.ts 常量）

# 3) 对拍（单命令封闭，约 16 分钟；期间严禁任何并发 GLM 推理——见纪律）
pnpm discount:verify

# 4) 判读：见下表
```

`verify-discount.sh` 内部时序：沉降 90s → 基线平台（连读 3 次一致）→ **空转本底窗**
150s 测漂移 → 探针 A → 平台 → 探针 B → 平台 → 探针 A → 平台 → 探针 B → 平台 →
汇总判定。全程 stderr 打逐窗读数，stdout 打结论。

## 四、判读

| 观测 | 含义 | 处置 |
| --- | --- | --- |
| 比值 A/B ∈ 0.50–0.75，双池互证 ✓，本底 0 | **折扣通道生效**（0.67 邻域），等效额度 = 1/比值 | 无 |
| 比值 ≈ 1.0（两臂同价） | 签名未生效（可能降级 fail-open 直发、协议常量升级被拒） | 查 `/zcode-plan status` 签名行；核对 `signing.ts` 常量 vs 官方客户端 |
| 某窗 u3Δ ≠ u6Δ | 窗口混入外部消费，读数被污染 | 重跑（脚本会显式标 ⚠ 作废提示） |
| 本底漂移 ≠ 0 | 池上有别的消费源（其他会话/实例） | 结论仍扣本底可用，但建议排查后重跑 |
| 探针 `cached>0` | 请求体撞了前缀缓存（不应发生：每发全新体） | 检查 gen.mjs 是否被改动 |

**实例读数（2026-11-04，同一账号同日两轮）**：

| 轮次 | 臂 A 刻度 | 臂 B 刻度 | 比值 | 等效 |
| --- | --- | --- | --- | --- |
| 11:05（验收 4.2，单对） | 0.952 | 1.543 | 0.617 | 1.62x |
| 16:13（复核，交错双对） | 2.021 | 2.976 | 0.679 | 1.47x |

绝对刻度同日翻倍（两臂同比、双池同步）——上游时段计量系数所致；比值稳定证明
折扣结构与时段系数正交。晨轮比值低于 0.67 可能含闲时叠加成分，午后轮 0.679 恰在
官方 0.67 邻域。

## 五、方法论：每个设计对应一类历史踩坑

1. **互异全新体（KV 缓存误判）**：缓存命中的输入按低价计费。历史「scene=1 Key →
   3–4 分/42k」折扣观察就是同体重复请求命中前缀缓存的假阳性（`cached_tokens=42048`
   存档在案）。gen.mjs 时间种子保证每发内容全新、臂间无共享前缀；归一公式仍保留
   `cached×1.7` 项兜底计权。
2. **理论积分归一（勿用分/ktoken）**：输出系数 24 = 输入 2.3 的 10 倍，输出长度波动
   会污染粗归一；请求体 `max_tokens=16` + thinking disabled 把输出压到可忽略。
3. **平台期轮询（聚合延迟）**：quota 上账有 1–2 分钟聚合延迟，「Δ≥5 就停」的早断
   法会截在记账半途；连读 3 次一致（15s 间隔）才算落定。
4. **空转本底窗**：150s 不发任何探针，池值仍在走 = 有外部消费源。本底从两臂合计里
   按窗数扣除。
5. **交错双对 A B A B**：任何 sporadic 背景突发均摊到两臂，比值不受单窗偶发污染；
   单发读数本身有 ±1 分粒度噪声，双对均值吸收。
6. **双池互证**：PAT 请求同时扣 u3（5h 窗）与 u6（周额度），正常应逐窗相等；不等
   即窗口被污染，判读作废。
7. **单命令封闭（自污染教训）**：dsh 主会话自身跑 GLM、与实验共享 quota 池——
   后台跑实验 + 前台并发推理会污染读数（历史「PAT 多扣 20%」即此假象）。对拍必须
   在一条命令内完成，期间主会话不产出 token。

## 六、纪律与边界

- **运行期间零并发推理**：`verify-discount.sh` 执行中不要在任何会话里跑 GLM 请求
  （包括本插件的 dsh 会话与其他 GUI 标签页）。
- **窗口尾部不跑**：5h 窗口余量不足时读数不可信，等窗口重置（`/zcode-plan status`
  用量行可见当前窗口）。
- **机密纪律**：快照点文件 0600 落 `WORK_DIR`（仓外）；脚本 stdout/诊断永不打印
  JWT / PAT / Key Secret 值；仓库里的脚本只含官方公开协议常量（与 `signing.ts`
   同源），不含任何机密。
- **成本预算**：4 探针 × 理论积分 ~8.4，按当前时段刻度实测 ~60–90 分（两池同扣）；
  跑前看一眼周额度余量。
- **聚合延迟**：脚本内部已含沉降与平台等待，无需手工等待。
