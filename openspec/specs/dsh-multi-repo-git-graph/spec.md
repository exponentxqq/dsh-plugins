# dsh-multi-repo-git-graph Specification

## Purpose
为 DSH Web GUI 提供「单工作区多 git 子仓」的仓库枚举与平铺分支芯片、单仓与跨仓（组）分支操作，并在放宽路径语义的同时守住工作区访问边界。

## Requirements

### Requirement: 工作区仓库枚举
系统 SHALL 在工作区根路径下枚举可用于 git 操作的仓库集合，包含工作区根仓（当其自身是 git 仓库时）与限定范围内的子仓；每个条目给出展示名、绝对路径与是否为根仓。

#### Scenario: 多仓工作区枚举
- **WHEN** 客户端对工作区根发起仓库枚举
- **THEN** 返回该工作区内全部被识别的仓库，根仓标记为 primary，其余按相对路径命名

#### Scenario: 工作区根不是仓库
- **WHEN** 工作区根自身没有 `.git` 而子目录中存在仓库
- **THEN** 返回子仓列表，且不含 primary 条目

#### Scenario: 无仓库工作区
- **WHEN** 工作区内不存在任何 git 仓库
- **THEN** 返回空列表，客户端不渲染任何仓库相关控件

### Requirement: 仓库扫描边界
系统 SHALL 按固定边界扫描仓库：下钻深度受限、发现仓库后不再进入其内部、跳过隐藏目录与依赖及构建产物目录、不跟随符号链接，并限制单次扫描访问的目录数量。

#### Scenario: 仓库内嵌套仓库
- **WHEN** 一个已识别子仓的内部还存在嵌套 git 仓库
- **THEN** 该嵌套仓库不出现在枚举结果中，也不影响外层仓库的识别

#### Scenario: 扫描预算耗尽
- **WHEN** 已访问目录数量达到单次扫描上限
- **THEN** 枚举在预算内收敛并返回已识别仓库，不使请求失败

#### Scenario: 符号链接目录
- **WHEN** 工作区内存在指向外部的符号链接目录
- **THEN** 扫描不进入该链接，结果中不包含其指向的仓库

### Requirement: 每仓状态聚合
每个被枚举的仓库 SHALL 附带状态快照：当前分支（分离 HEAD 表示为空）、HEAD 短标识、脏文件数、未跟踪文件数、冲突数与是否存在进行中的 git 操作。

#### Scenario: 总览一次取回全部状态
- **WHEN** 客户端渲染多仓芯片行
- **THEN** 单次请求返回全部仓库及其状态，无需逐仓轮询

#### Scenario: 条目不再是可用仓库
- **WHEN** 某条目对应路径在两次扫描之间不再是一个可用仓库
- **THEN** 该条目状态为不可用，而不是导致整体请求失败

### Requirement: 组切换的隐式特性集语义
组切换 SHALL 以分支名隐含定义参与仓：对工作区内拥有该分支名的仓库执行切换；缺少该分支的仓库 MUST 被跳过并标记为未包含。

#### Scenario: 部分仓库缺分支
- **WHEN** 用户对分支名 `feat/x` 执行组切换，而 portal 仓库没有该分支
- **THEN** 其余仓库切换到 `feat/x`，portal 记为未包含且不为其创建分支

#### Scenario: 全部仓库都缺分支
- **WHEN** 没有任何仓库拥有所请求的分支名
- **THEN** 组切换不产生任何变更，并逐仓报告未包含

### Requirement: 组切换的预检原子性
组切换 MUST 先对所有参与仓完成守卫预检（未解决冲突、进行中的 git 操作、分支已被其他 worktree 检出）；任一仓未通过时 MUST NOT 对任何仓库执行切换。

#### Scenario: 单仓守卫失败
- **WHEN** 参与仓之一存在未解决冲突
- **THEN** 全部仓库保持原分支，结果中该仓给出稳定错误原因，其余仓标记为未执行

#### Scenario: 预检全部通过
- **WHEN** 所有参与仓均通过预检
- **THEN** 各仓在本次操作中被执行切换并逐仓返回结果

### Requirement: 组新建分支
组新建 SHALL 在用户勾选的仓库集合中创建同名新分支；默认以各仓各自的默认主线为基准，并允许改为以各仓当前 HEAD 为基准；任一仓库失败 MUST NOT 阻止其他仓库完成，且 MUST NOT 自动回滚已创建的分支。

#### Scenario: 默认基准为各仓主线
- **WHEN** 用户勾选多个仓库并新建分支且保持默认基准
- **THEN** 每个仓库从自己的默认主线创建该分支

#### Scenario: 基准改为各仓当前 HEAD
- **WHEN** 用户将基准切换为「各仓当前 HEAD」
- **THEN** 每个仓库从自己当前的 HEAD 创建该分支

#### Scenario: 单仓创建失败
- **WHEN** 某个勾选仓库因分支已存在或名称非法而失败
- **THEN** 其余仓库仍完成创建，结果逐仓给出成功或失败原因

### Requirement: 组操作结果汇报
组操作 SHALL 逐仓返回结果，区分成功、跳过（未包含）与失败，并给出稳定错误原因供界面呈现与单仓重试。

#### Scenario: 混合结果
- **WHEN** 一次组操作中部分仓成功、部分仓被跳过、部分仓失败
- **THEN** 界面按仓分列三类结果，失败仓可单独重试

### Requirement: 访问门控与工作区围栏
`/git/*` SHALL 只接受位于某个已注册工作区之内（或等于该工作区根）的路径，且解析出的 git 顶层目录 MUST 仍位于同一工作区内；否则请求 MUST 被拒绝。

#### Scenario: 工作区外的路径
- **WHEN** 客户端提交一个不属于任何已注册工作区的路径
- **THEN** 请求被拒绝并返回 workspace-unknown

#### Scenario: 工作区内子目录
- **WHEN** 客户端提交工作区内的子目录路径，且该目录属于工作区内的某个仓库
- **THEN** 请求按该仓库执行

#### Scenario: git 顶层逃出工作区
- **WHEN** 提交的路径位于工作区内，但解析出的 git 顶层目录落在工作区之外
- **THEN** 请求被拒绝，而不是对该外部仓库执行操作

### Requirement: 单仓工作区回归
当工作区内只有一个可用仓库时，芯片与弹出层 SHALL 与该仓库的单仓行为一致，MUST NOT 呈现仓库切换或组操作控件。

#### Scenario: 单仓工作区
- **WHEN** 工作区只有一个 git 仓库
- **THEN** 芯片直接显示该仓分支，弹出层不呈现仓库切换与组操作控件

### Requirement: 无遥测上报
插件 MUST NOT 向任何外部端点发送安装或使用遥测。

#### Scenario: 客户端加载
- **WHEN** 客户端插件在浏览器中加载
- **THEN** 不产生指向第三方遥测端点的网络请求

### Requirement: 组切换候选的平铺选择
组切换对话框 SHALL 以可点选的平铺候选呈现工作区内的分支名，每个候选 MUST 显示其覆盖的仓库数；MUST NOT 使用原生下拉选择控件；没有任何候选时 MUST 给出空态提示且组切换不可执行。

#### Scenario: 候选与覆盖率
- **WHEN** 用户打开组切换对话框，且工作区内多个仓库共享分支名 `feat/x`
- **THEN** 候选区平铺显示 `feat/x` 及其覆盖率（如 2/4），可点选为当前候选

#### Scenario: 仅单仓拥有的分支名
- **WHEN** 某分支名只存在于一个仓库
- **THEN** 该候选仍可点选，其覆盖率显示为 1/N，执行组切换时只有该仓库参与

#### Scenario: 无任何候选
- **WHEN** 工作区内没有任何仓库提供分支名
- **THEN** 候选区给出空态提示，组切换不可执行

### Requirement: 宿主组件体系一致性
客户端界面 SHALL 复用宿主提供的 `@deepseek-ai/dsh-client-ui-primitives` 组件（按钮、模态、标签、状态点、勾选、输入、分段控件、提示气泡、菜单表面与临时横幅），MUST NOT 自绘等价控件或使用原生下拉选择控件；该包 MUST 保持为客户端 bundle 的唯一 UI 外部依赖，MUST NOT 引入新的运行时依赖。

#### Scenario: 对话框行为
- **WHEN** 用户打开任一对话框（创建分支、创建 worktree、Git 图谱、worktree 管理、组切换、组新建、组结果）
- **THEN** 对话框以宿主模态呈现，支持 Escape 与遮罩点击关闭，关闭后焦点回到打开它的控件

#### Scenario: 不使用原生下拉与原生勾选
- **WHEN** 界面呈现基准选择、仓库勾选或组切换候选
- **THEN** 分别以宿主分段控件、宿主勾选与平铺候选呈现，不出现原生下拉选择控件

#### Scenario: 长分支名可读
- **WHEN** 分支名超出所在行的可显示宽度
- **THEN** 悬停或聚焦该行时以宿主提示气泡给出完整名称

### Requirement: 操作反馈与忙碌态
仓库分支切换成功后，客户端 SHALL 以宿主临时横幅给出成功反馈，且该反馈 MUST 在弹层关闭后仍然可见；失败原因 MUST 以内联文本停留在触发它的面板或对话框中；进行中的操作 MUST 呈现忙碌态并 MUST NOT 接受重复提交。

#### Scenario: 切换成功的反馈
- **WHEN** 用户在任一仓库面板选择另一分支且切换成功
- **THEN** 弹层关闭，并以宿主临时横幅提示已切换到该分支

#### Scenario: 切换失败的停留
- **WHEN** 切换被拒（例如目标分支已在其他 worktree 检出）
- **THEN** 弹层保持打开，失败原因内联显示在面板中

#### Scenario: 忙碌时禁止重复提交
- **WHEN** 一个组操作或切换请求仍在进行中
- **THEN** 相关按钮与候选处于禁用态，重复点击不产生第二次请求

### Requirement: 多仓平铺分支芯片
多仓工作区的上下文行 SHALL 为每个被枚举的仓库各呈现一个分支芯片，根仓优先、其余按名称排序；芯片标签 MUST 为 `仓库名 · 分支`（分离 HEAD 与不可用各有稳定文案），脏文件数大于零时 MUST 以徽章给出数量；不可用仓库的芯片 MUST 以降级样式呈现且不可打开。每个芯片 SHALL 直接打开该仓库自己的分支面板，其操作 MUST 只作用于该仓库。工作区 MUST NOT 再呈现全仓总览面板。

#### Scenario: 平铺与顺序
- **WHEN** 多仓工作区的空白会话渲染芯片行
- **THEN** 每个仓库各有一个芯片，根仓排在最前，其余按名称排序

#### Scenario: 各自分支可见
- **WHEN** 部分仓库处于不同分支或存在未提交更改
- **THEN** 每个芯片显示自己仓库的当前分支，脏文件数以徽章给出，无需打开任何面板

#### Scenario: 打开即本仓面板
- **WHEN** 用户点击某个仓库的芯片
- **THEN** 直接打开该仓库的分支面板，其中不出现其他仓库的分支，也不出现仓库切换入口

#### Scenario: 操作隔离
- **WHEN** 用户在某个仓库的面板中切换或创建分支
- **THEN** 仅该仓库被改变，其余仓库的分支保持不变

#### Scenario: 不可用仓库
- **WHEN** 某个仓库的枚举状态为不可用
- **THEN** 其芯片以降级样式显示「不可用」且点击不打开面板

### Requirement: 操作与视图分离
分支面板 MUST 只承载视图内容（搜索、分支列表、脏文件行与内联错误）；分支创建、Git 图谱、worktree 会话与 worktree 管理 MUST NOT 以并排按钮直接混排在视图区，而 SHALL 收敛为单一「更多操作」入口，推入独立的操作面板后按分组列出，并可返回分支列表。

#### Scenario: 面板只呈现视图
- **WHEN** 用户打开任一仓库的分支面板
- **THEN** 面板内只有搜索、分支列表与状态提示，操作入口收敛为一个「更多操作」行

#### Scenario: 推入操作面板
- **WHEN** 用户点击「更多操作」
- **THEN** 面板切换为操作面板，操作按「分支」「Worktree」分组列出，并提供返回分支列表的入口

#### Scenario: 操作各自打开对话框
- **WHEN** 用户在操作面板中选择任一操作
- **THEN** 打开对应的宿主对话框，且操作只作用于该面板所属仓库

### Requirement: 组操作归属根仓
组切换与组新建 MUST 只出现在根仓库芯片的操作面板中；非根仓库芯片 MUST NOT 呈现任何组操作入口。组切换 SHALL 以对话框承载候选与确认，组新建 SHALL 沿用勾选仓库与基准的对话框；两者的逐仓结果 SHALL 由结果面板汇报，并允许对失败仓单独重试。

#### Scenario: 根仓承载组操作
- **WHEN** 用户打开根仓库芯片的操作面板
- **THEN** 操作面板在「分支」「Worktree」之外多出一组「组操作」，含组切换与组新建

#### Scenario: 非根仓没有组操作
- **WHEN** 用户打开任一非根仓库芯片的操作面板
- **THEN** 面板中不出现组操作分组，也不出现任何组操作入口

#### Scenario: 组切换对话框
- **WHEN** 用户在根仓操作面板选择组切换
- **THEN** 打开组切换对话框，平铺候选带覆盖率，确认后逐仓执行并由结果面板汇报

### Requirement: 多仓变更推送
系统 SHALL 在已订阅仓库的状态发生外部变化时推送变更，使芯片无需手动刷新即可更新。客户端 MUST 以一条共享流订阅工作区内全部被枚举的仓库，MUST NOT 为每个仓库各开一条流。

#### Scenario: 外部切换分支
- **WHEN** 终端在某个仓库中切换分支
- **THEN** 订阅方在轮询周期内收到变更并刷新该仓状态与芯片

#### Scenario: 枚举结果变化后重订阅
- **WHEN** 工作区仓库集合变化（新增、移除或不再可用）
- **THEN** 订阅按新的仓库集合重建，已移除仓库的推送不再驱动界面
