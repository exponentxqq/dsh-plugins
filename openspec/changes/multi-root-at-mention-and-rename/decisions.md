## 第 1 轮（前沿 = Q1–Q5，5 问）

### Q1 裸模糊查询是否跨根合并（行为决策）

- **问题**：`@` 裸模糊（无 `/` 非空，如 `@test`）是否同时模糊搜索附加根文件。
- **过程**：首轮用户要求详细解释；补充两种查询模式（钻入 vs 裸模糊）说明、实际环境举例（主根 dsh-plugins + 附加根 /home/docker）、四维对比（发现性 / 性能内存 / 结果噪音 / 实现复杂度）后重问。
- **答复**：**不合并**——裸模糊只搜主根；附加根经钻入可达（空 query 每根一条候选 + 绝对路径钻入）。
- **依据**：附加根为大目录时全量索引首查卡顿；上游排名单根设计，跨根混杂淹没主根结果；钻入路径已全覆盖，合并收益小于成本。
- **仍待决**：无。

### Q2 空 query 附加根候选形态（UX 决策）

- **问题**：空 query 时附加根以什么形态进入候选列表。
- **答复**：**每根一条目录候选**（如 `/home/x/develop/docker/`，尾斜杠保持钻入），追加在原结果之后。
- **依据**：克制、不淹没主根顶层结果；点根钻入即可展开。
- **仍待决**：无。

### Q3 附加根内检索载体（技术选型）

- **问题**：附加根内的目录钻入检索用什么实现。
- **答复**：**动态 `import()` 复用上游 `WorkspaceFileSearch`**（`@deepseek-ai/dsh-file-reference-local` 公开导出）。
- **依据**：排除目录表、排名、逐段 `lstat` 拒 symlink 语义全继承，与主根行为一致；不变量 8 约束下按需加载（先例 `src/compat/llm-message.ts`）。
- **仍待决**：无。

### Q4 版本号与发布节奏（发布决策）

- **问题**：本次变更（改名 + @ 补全）的版本与发布。
- **答复**：**两批次并入下一次 release，`v1.3.0`（minor）**。
- **依据**：新增能力作 minor；安装锚点 path 变化在单用户私有仓不构成 major 的实际负担。
- **仍待决**：无。

### Q5 决策记录归属（文档惯例）

- **问题**：@ 补全扩展的 ADR 归属。
- **答复**：**新开 ADR-0012**（@ 补全 consumer 扩展是独立决策主题），ADR-0011 保持封存；改名在 proposal/design 记录，不占 ADR。
- **依据**：一个 ADR 一个决策主题的既有惯例（ADR-0001…0011 均单主题）。
- **仍待决**：无。

## 收敛结论

**前沿为空，全部待决项已由用户拍板，无静默假设。**

汇总行为边界（落档输入）：

1. 裸模糊 query：不干预，原样透传（上游只搜主根）。
2. 空 query / 顶层 query：原结果后追加每个 available 附加根一条绝对路径目录候选（尾斜杠钻入）。
3. 绝对路径 query 落在附加根内：以该根检索，产出绝对路径候选，I/O 后复验 scope。
4. 绝对路径 query 为附加根前缀：前缀匹配追加根目录候选。
5. 无附加根：字节级透传；卸载恢复描述符。
6. 新行 `multi-root-file-references`（inject `multiRootCompat`），兼容契约三处同步（OPTIONAL_CORE_PACKAGES / exact peers / dev pin 两包）。
7. 目录改名先行（零行为批次），功能批次随后；`v1.3.0` 一次发布；新开 ADR-0012。
