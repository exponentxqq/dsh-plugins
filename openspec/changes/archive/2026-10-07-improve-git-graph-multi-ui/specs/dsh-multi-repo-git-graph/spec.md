# Spec Delta

## MODIFIED Requirements

### Requirement: 全仓总览呈现
客户端 SHALL 在分支芯片的弹出层中以宿主菜单表面呈现工作区全部仓库的概览，每个仓库行给出仓库名（根仓带徽章）、当前分支、状态标识与脏文件数（脏时以警示标签给出），根仓优先、其余按名称排序，使分支对齐与掉队可直接观察。

#### Scenario: 打开总览
- **WHEN** 用户在空白会话点击分支芯片
- **THEN** 弹出层展示全部仓库的概览行，根仓优先，其余按名称排序

#### Scenario: 分支掉队可见
- **WHEN** 部分仓库处于与其余仓库不同的分支
- **THEN** 概览行按仓库分别显示各自分支，用户可直接比较

#### Scenario: 仓库状态一眼可辨
- **WHEN** 某个仓库存在未提交更改或已不可用
- **THEN** 该行以状态标识与警示标签给出对应状态，干净仓库同样有状态标识但不带警示标签

#### Scenario: 自描述行不依赖列头
- **WHEN** 总览渲染任意数量的仓库行
- **THEN** 每行自描述其仓库名、分支与脏文件数，无需列头文字辅助阅读

## ADDED Requirements

### Requirement: 组切换候选的平铺选择
总览的组切换入口 SHALL 以可点选的平铺候选呈现工作区内的分支名，每个候选 MUST 显示其覆盖的仓库数；MUST NOT 使用原生下拉选择控件；没有任何候选时 MUST 给出空态提示且组切换不可执行。

#### Scenario: 候选与覆盖率
- **WHEN** 用户打开总览，且工作区内多个仓库共享分支名 `feat/x`
- **THEN** 候选区平铺显示 `feat/x` 及其覆盖率（如 2/4），可点选为当前候选

#### Scenario: 仅单仓拥有的分支名
- **WHEN** 某分支名只存在于一个仓库
- **THEN** 该候选仍可点选，其覆盖率显示为 1/N，执行组切换时只有该仓库参与

#### Scenario: 无任何候选
- **WHEN** 工作区内没有任何仓库提供分支名
- **THEN** 候选区给出空态提示，组切换不可执行

### Requirement: 宿主组件体系一致性
客户端界面 SHALL 复用宿主提供的 `@deepseek-ai/dsh-client-ui-primitives` 组件（按钮、模态、标签、状态点、勾选、输入、分段控件、提示气泡、菜单表面与临时横幅），MUST NOT 自绘等价控件或使用原生下拉选择控件；该包 MUST 保持为客户端 bundle 的唯一 UI 外部依赖，MUST NOT 引入新的运行时依赖。

#### Scenario: 对话框行为
- **WHEN** 用户打开任一对话框（创建分支、创建 worktree、Git 图谱、worktree 管理、组新建、组结果）
- **THEN** 对话框以宿主模态呈现，支持 Escape 与遮罩点击关闭，关闭后焦点回到打开它的控件

#### Scenario: 不使用原生下拉与原生勾选
- **WHEN** 界面呈现基准选择、仓库勾选或组切换候选
- **THEN** 分别以宿主分段控件、宿主勾选与平铺候选呈现，不出现原生下拉选择控件

#### Scenario: 长分支名可读
- **WHEN** 分支名超出所在行的可显示宽度
- **THEN** 悬停或聚焦该行时以宿主提示气泡给出完整名称

### Requirement: 操作反馈与忙碌态
单仓切换分支成功后，客户端 SHALL 以宿主临时横幅给出成功反馈，且该反馈 MUST 在弹层关闭后仍然可见；失败原因 MUST 以内联文本停留在触发它的面板或对话框中；进行中的操作 MUST 呈现忙碌态并 MUST NOT 接受重复提交。

#### Scenario: 切换成功的反馈
- **WHEN** 用户在单仓面板选择另一分支且切换成功
- **THEN** 弹层关闭，并以宿主临时横幅提示已切换到该分支

#### Scenario: 切换失败的停留
- **WHEN** 切换被拒（例如目标分支已在其他 worktree 检出）
- **THEN** 弹层保持打开，失败原因内联显示在面板中

#### Scenario: 忙碌时禁止重复提交
- **WHEN** 一个组操作或切换请求仍在进行中
- **THEN** 相关按钮与候选处于禁用态，重复点击不产生第二次请求
