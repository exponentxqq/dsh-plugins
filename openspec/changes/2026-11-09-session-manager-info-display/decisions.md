## 第一轮后的补充查证（事实，非提问）

- **zstd 帧结构实测**（1134 条真实归档条目，本机 `~/.dsh/archive/sessions`）：
  - `zstdDecompressSync` 一次只解**第一个帧**（恰为 header 行，214 字节级）——`createdAt`/`cwd`/`agentPreset` 可白得且近零成本；流式 `createZstdDecompress` 同样不出第二帧。
  - title 事件在后续帧：**99.5%（1128/1134）首个 title 位于解压文本前 256KB 内**（128KB 仅 3.6%）；全文解压 p50≈972KB、p99≈15.6MB——全量解压不可取，须**帧边界结构扫描 + 逐帧解压 + 首个 title 命中即停**。
  - **陈旧率 6.1%**（69/1128 首 title ≠ 末 title，all-prompts 再生成所致）——Q1-B 近似语义的量化代价。
  - **0.5%（6 条）无 title 事件**——Q2 回退必要性的量化依据。
  - 帧边界扫描（magic + FHD + Window_Descriptor + Dictionary_ID + FCS + 块头循环 + 校验和，上游 `scanZstdFrames` 同款算法）在全部 1134 个文件上 0 失败；注意 Window_Descriptor 字节在 Single_Segment=0 时存在（首版脚本漏掉即全零，已修正验证）。
- 帧扫描器/解压工具上游包**不经 exports 导出**，须在本插件内实现（约百行，`node:zlib` 自带，无新依赖）。
- `node:zstd` 内建模块在 Node 24.21 不存在；zlib 的 zstd API 为正确入口（上游 jsonl 包同款）。

## 裁定与结论（收敛终态）

1. 标题来源 = 列表时读归档日志前缀；字节预算 = **256KB 解压文本、帧粒度推进、预算内未命中即回退短码目录名**（预算为实测事实裁定：99.5% 命中；非用户拍板项，如需调整属工程参数）。
2. spec 语义改写方向：`dsh-web-ux-session-manager`「已迁移会话管理」的「会话标识取目录名……不承诺会话标题」改为「标题尽力显示（前缀内首个 title 事件，不承诺最新），缺失回退目录名短码」；「批量线上契约」补 `MigratedEntry` 新字段。`dsh-web-ux-session-delete` **不动**。
3. 工程细节（不待用户，设计期定）：fork 徽标判定 = parentSessionId 非空且非 subagent；cwd 显示取尾段、悬停全路径；域计数徽标口径 = 当前可见行数（过滤后）；解压并发受限（复用 listConcurrency 思路，逐条失败降级不阻塞列表）。
4. 前沿为空，未答项零——达成共识，可进阶段 1.7 代码设计。
